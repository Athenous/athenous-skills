# Marketing Report Generator

## Purpose

Turn verified marketing data into a concise, decision-oriented report.

## Use this Skill when

Use to analyze marketing outcomes or define measurement. Confirm the reporting period, business objective and metric definitions before interpreting results.

## Required context

- report audience
- period
- goals
- exports
- metric definitions
- targets/prior period
- narrative context
- template

If evidence is incomplete, provide a scoped analysis and list what cannot be concluded. Never fabricate metrics, benchmarks or causal explanations.

## Specialized workflow

1. Inventory and reconcile sources
2. select goal-linked metrics
3. compare target, prior period and trend
4. explain material movements with evidence
5. distinguish activity from outcomes
6. surface risks and decisions
7. tailor depth to reader.

## Deliverables

- Executive summary
- KPI dashboard
- channel insights
- decisions needed
- next-period actions
- metric appendix.

## Quality gates

- Define formulas, denominators, units, time zones and attribution windows.
- Compare like-for-like periods, cohorts and segments.
- Distinguish platform attribution, blended business outcomes and causal incrementality.
- Report missingness, tracking changes and uncertainty prominently.
- Tie recommendations to a decision, not just a metric movement.



## Ready-to-use workflow

```text
Use marketing-report-generator for [team/client/business]. Desired result: [outcome]. Current process/context: [describe]. Scope and deadline: [details]. Systems/data available: [list or paste]. Constraints: [permissions, privacy, budget, tools]. Check: report audience; period; goals; exports; metric definitions; targets/prior period; narrative context; template. Ask only one blocking clarification; otherwise document assumptions and provide the complete operational deliverables. Do not claim a workflow or change was deployed unless verified.
```

### Execution checklist

1. Confirm the requester, intended users, business outcome, scope, deadline and authority to act.
2. Map existing process, source data, systems, roles, dependencies and failure modes.
3. Apply the specialized workflow above. Make each recommendation operational with inputs, steps, owner and acceptance criteria.
4. Check privacy, client separation, least privilege, reversibility, exception handling and auditability.
5. Deliver a rollout/test plan and distinguish proposed design from changes actually made.

Also include assumptions, risks, dependencies, open questions, rollout sequence and measurable acceptance criteria. Use **Not provided** for missing facts; never claim configuration or execution without tool confirmation.

## Athenous MCP usage

MCP is optional. If connected, discover actual reporting and analytics tools and exact schemas at runtime. Use only authorized workspaces and verified data fields; never assume metrics or integrations exist. Keep client data isolated. If a data source is unavailable, use supplied exports and disclose the gap.

## Safety

Use aggregate data where possible and protect personal information. Do not expose customer-level records unnecessarily. Analysis does not authorize budget or campaign edits; obtain explicit confirmation before consequential writes and never claim success without tool confirmation.
