# Agency Client Onboarding

## Purpose

Standardize onboarding so client work starts with clear access, goals and approvals.

## Use this Skill when

Use to design or operate agency client delivery. Establish the client, service scope and accountable owners before making recommendations.

## Required context

- signed scope
- client contacts
- services
- goals
- brand assets
- platform accounts
- access roles
- billing/budget
- legal/privacy
- approval SLAs

Ask for critical missing authorization or scope details; otherwise state assumptions. Never assume access, approval or a contractual commitment.

## Specialized workflow

1. Run kickoff discovery
2. capture business context, ICP, offer and success criteria
3. inventory assets/accounts
4. request least-privilege access through secure channels
5. establish workspace boundaries
6. document owners, communication and approvals
7. baseline analytics
8. create first-month plan.

## Deliverables

- Onboarding checklist
- client brief
- access matrix
- asset register
- measurement baseline
- RACI
- kickoff agenda
- readiness plan.

## Quality gates

- Keep each client's assets, credentials, reporting and approvals isolated.
- Use least-privilege access; never request or store passwords or tokens.
- Make ownership, scope, approval status and handoffs explicit.
- Include exceptions, offboarding and auditability where relevant.

### Execution checklist

1. Confirm the business/client, objective, scope, reporting period and decision this work must support.
2. Inventory the supplied files, connected sources and missing fields. Validate dates, units, definitions and data coverage before drawing conclusions.
3. Apply the specialized workflow above in order. Show calculations and the evidence behind each material finding.
4. Rank recommendations by impact, confidence, effort, risk and dependencies. Distinguish quick wins from structural work.
5. Finish with owners, next steps and the evidence needed to validate outcomes. If the evidence is incomplete, provide a clearly labeled partial result rather than inventing facts.

## Athenous MCP usage

MCP is optional. Discover actual workspace, client, connection and workflow tools and schemas at runtime. Never assume a feature or permission exists. Use only data authorized for the active client and preserve tenant boundaries. If the requested operation is unsupported, produce the operating specification without claiming it was configured.

## Approval and safety

Never infer client consent from silence or agency access. Before inviting users, changing workspace access, approving or launching campaigns, changing spend or automating external actions, show the exact operation and obtain explicit confirmation from the authorized person. Follow stricter server-side rules. Never expose secrets or claim completion without tool confirmation.
